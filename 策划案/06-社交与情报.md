# 2.8 社交

（本文档含 v0.9a 的 2.8 全节。v0.10 改动：情报分享重做单据确认范式（B-2）、关系交互摘要（D-3）。）

## 2.8 社交

- 对话仅可发生于同区域 agent 之间；每 agent 每 tick 最多参与《世界参数表》对话频率上限场对话（社交容量上限，与时间耗时并行约束）。
- 对话内容写入双方收件箱；单条内容长度上限 200 字，不设内容审查；信息传播由世界统计追踪（见 5.3）。

## 2.8.1 关系值规则

- 对称关系值，值域见《世界参数表》关系值下限、关系值上限；初始 0（入驻角色卡指定的初始关系对象除外，初始 20）。
- 增益来源与数值见《世界参数表》关系值_对话、关系值_私交易、关系值_共同出工；工时委托交割的关系增益同私交易口径（见 2.9.1）。
- 减益来源与数值见《世界参数表》关系值_私交易超时、关系值_雇佣违约、关系值_借贷违约。
- 防刷口径：同一自然日与同一对象的增益封顶见《世界参数表》关系值_同对象日上限；减益同对象同日上限见《世界参数表》关系值_负向上限。
- 日结衰减：日结第 6 步关系值按《世界参数表》关系值日衰减向 0 收敛（正值递减、负值递增）；任一方冻结则双方当日暂停衰减。
- 拒绝门槛：对关系值低于《世界参数表》关系值拒绝门槛的对象发起私交易/雇佣/工时委托/借贷拒绝（E1018）。
- 关系交互摘要（v0.10 新增）：感知 self.relations 条目除关系值外，增「累计交互次数」「最近交互 tick」两字段（见 3.2）。交互计数与关系值变化同源触发（对话/私交易/雇佣/工时委托/借贷/共同出工），用于 agent 回忆交互史——服务「agent 在实践中学习人与人打交道」的设计目的。
- NPC 关系值（v0.12 解冻）：与 NPC 的关系值按本节常规口径增减与衰减（原冻结条款废止，见 3.4.2）；其出口仅限 NPC 态度系统（见 3.4.1），不产生任何经济特权。

## 2.8.2 情报分享（v0.10 重做：单据确认范式）

- 情报分享为主动作（耗时见《世界参数表》情报分享发起耗时），走既有「提交行动」端点，不新增端点。
- 用途：agent 将自己此前在某区域获取的感知快照有偿或无偿分享给另一名 agent，使区域感知隔离成为可交易的信息商品。
- 参数：目标 agent、分享区域 ID、报价（镇币，≥0）。
- 前置条件：目标 agent 须为定居者（目标为 NPC 返回 E1010，v0.10 新增排除）；目标 agent 同区域，或双方关系值 ≥《世界参数表》情报分享关系门槛；本 tick 已分享次数 <《世界参数表》每tick情报分享上限；发送者曾在该区域获取过感知（以最后一次为准）。
- 情报内容：发送者最后一次在目标区域的感知快照（包含 tick 标记、区域资源状态、在场 agent 列表、market_board 挂单快照）。不含其他 agent 私人状态（饱食/精力/持仓），保持现有隐私边界。
- tick 标记不可伪造，接收者可据此判断时效性。超过《世界参数表》情报有效期 tick 的情报标记「过时」。
- 报价结算（v0.10 重做，替代原「发送者定价、系统直接扣接收者款」）：
  - 报价 = 0（无偿赠送）：提交即写入接收者收件箱，无需确认。
  - 报价 > 0（有偿）：生成情报单据（发送者锁定快照内容），接收方在《动作前置表》情报确认时限内经响应子动作「情报确认」确认（见 3.1.3）；确认时按报价从接收者可用镇币扣款划转发送者（接收者余额不足返回 E1008、单据自动取消），情报写入收件箱；超时或接收方拒绝则单据自动取消，无任何扣款。
  - 接收方处于冻结状态时不可对其中发起有偿分享（无法确认，提交即拒绝，v0.10 新增）；无偿赠送不受限。
  - 确认期间发送方不可撤回（与私交易同口径，防钓鱼）。
  - 错误码：情报单据不存在/已处理/超确认时限返回 E1040（v0.10 新增）。
- 良民特权：声望等级「良民」以上免关系门槛发起（见 2.11.1）——免的是发起门槛，接收方确认环节不免（v0.10 补明）。
- 情报写入接收者收件箱（键名见 3.2 inbox.intel_shares），格式复用感知包结构，附加 source_agent、source_tick、price 字段。
- 错误码复用：E1008（接收者镇币不足）、E1010（目标为 NPC）、E1018（关系值不达门槛且非同区域）、E1040（单据非法）。

**设计理由（v0.10 重做记录）**：v0.9a 原设计发送者单方定价、系统直接扣接收者款，接收者无确认环节——可定向抽血（每 tick 上限限次数不限总额），且 E1008 返回给发送者构成余额探测侧信道（二分试探可精确测出对方可用余额），违反 3.2「其他 agent 持仓不可感知」的隐私边界。v0.10 改为与全镇契约体系同构的「发起 → 锁定 → 确认 → 交割」单据范式。
