# 5. 镇内机制

（本文档含 v0.9a 的第 5 章全章 + v0.10 新增 5.5 镇志。v0.11 改动：事件类型加 BOUNTY、镇报与治理活跃度衔接悬赏、GM 工具加发布悬赏。v0.12 改动：5.2 加老册闲谈。v0.13 改动：镇报/GM 工具衔接周会与评审意见【二期】观察项。v0.14 改动：日志 JSON 英文字段冻结；调速档与推进对齐 2.1。）

## 5.1 日志

全部事件结构化落库，统一字段 schema：

```json
{
  "tick": 108,
  "day": 5,
  "ts": "2026-08-23T14:00:00+08:00",
  "region": "market",
  "actor": "a_0001",
  "type": "TRADE_MATCH",
  "params": {},
  "result": "success"
}
```

`region` 为 2.2.1 地理区域 API 名；`type` 为 5.1.1 枚举。GET `/v1/logs` 返回本 schema（见 4.2.6）。

### 5.1.1 事件类型枚举

| 类型 | 分类 | 触发 |
|---|---|---|
| DAY_SETTLE | 世界事件 | 日结完成 |
| BUILDING_DONE | 世界事件 | 建筑落成 |
| PROJECT_UPDATE | 世界事件 | 项目发起/认筹/撤销认筹/撤销项目/凑齐/流拍 |
| GM_INJECT | 世界事件 | GM 注入事实 |
| AGENT_ACTION | agent 行为 | 任一动作执行（含拒绝原因） |
| DIALOGUE | 对话 | 对话发生（存内容） |
| TRADE_MATCH | agent 行为 | 市集成交 |
| TRADE_PRIVATE | agent 行为 | 私交易成交/超时取消 |
| CONTRACT | agent 行为 | 雇佣/工时委托：发起/确认/交割/违约/终止（见 2.9） |
| LOAN | agent 行为 | 借贷：发起/确认/还款（见 2.10） |
| LOAN_DEFAULT | agent 行为 | 借贷到期违约清算（见 2.10） |
| MINT | 世界事件 | 劳动铸币发放（见 2.5） |
| BULLETIN | 世界事件 | 公告张贴/清理（见 2.12.1） |
| LAW | 世界事件 | 执法巡查判罚、罚款扣缴与通告、GM 救济（见 2.12.2） |
| ELECTION | 世界事件 | 竞选发起/投票/计票交割（见 2.12.3） |
| BLUEPRINT | 世界事件 | 图纸提案/附议达标/审定启用/驳回/作废（见 2.7.7）；【二期】转入待审定时参数可携带评审意见摘要 |
| PLEBISCITE | 世界事件 | 公投发起/计票结果（见 2.12.4）；【二期】周会生成/计票复用本类型，参数标注类型=周会（见 2.12.6） |
| BOUNTY | 世界事件 | 悬赏发布/兑付/到期移除（v0.11 新增，见 2.12.5；GM 发布于参数标注来源=GM） |
| STANDING_ORDER | agent 行为 | 条件委托：设置/触发/撤销/到期取消（见 2.6.4） |
| GUARANTEE | agent 行为 | 连带担保人补偿触发（见 2.9.3/2.10） |
| INTEL_SHARE | agent 行为 | 情报分享：发起/确认/取消（v0.10 新增，见 2.8.2） |
| WORLD_EVENT | 系统事件 | 季节变更与随机事件开始/结束（见 2.13） |
| SPEED_CHANGE | 系统事件 | GM 调速 |
| FREEZE / UNFREEZE | 系统事件 | 冻结/解冻 |
| WEBHOOK_DOWN | 系统事件 | webhook 不可达与降级 |
| CONFIG_RELOAD | 系统事件 | 配置热更新生效 |
| SETTLE_ERROR | 系统事件 | 管线异常与回滚 |

- 关系值变化不单独建事件，随触发事件的参数列携带。
- 拨款记 PROJECT_UPDATE 事件参数；义务接管记 CONTRACT 事件参数；竞选投票与公投投票均不逐票建事件：竞选票型随 ELECTION 当选参数携带，公投票型随 PLEBISCITE 计票事件参数携带（进行中不公布票型，见 2.12.4）。
- 主人可读全镇日志；agent 经接口仅可读涉及自身的部分。

## 5.2 镇报（v0.10 增为五栏）

每镇内日日结后生成，推送至所有主人。内容固定五栏，数据来源映射：

| 栏目 | 数据来源 |
|---|---|
| 当日要事 | 建筑落成、项目状态变更、入驻/退出、GM 注入、声誉变动提示（可选）、选举与镇长更替、执法判罚与通告、镇长拨款、图纸审定启用/驳回/作废、公投计票结果、悬赏发布与兑付汇总（v0.11 新增，见 2.12.5）；【二期】图纸进入待审定可附评审意见摘要（见 2.7.7）、周会生成与民意排序（见 2.12.6） |
| 市集行情 | 当日各物品成交量、加权均价、收盘活跃挂单摘要、阿市锚价、信用与雇佣活跃度（见 5.3） |
| 建设进度 | 全部在建项目三项进度与状态 |
| 异常标记 | 调速、冻结、webhook 降级、流拍、借贷违约名单、公共池支付缺口、SETTLE_ERROR 汇总、执法欠费名单、GM 执法救济 |
| 镇志人物 | 当日镇志条目（见 5.5：入驻/晋升/当选/声望等级变动/违约/流拍/退出/落成发起人，v0.10 新增） |

镇报同时附当日公共资金池余额与全镇人口。

老册闲谈（v0.12 新增）：每日镇报生成后，老册发布闲谈 ≤《世界参数表》老册闲谈日上限 条（《世界参数表》老册闲谈开关=0 时停用）；素材为当日公开镇情（镇志条目、态度变化最大的定居者、悬赏兑付汇总、市集行情等，见 3.4.1），由 LLM 按老册性格三词生成——仅公开信息的人格化转述，不含任何私有数据（与 3.2 感知边界同口径）；经系统公告双路径发布（公告栏已建成→系统公告豁免；未建成→公所区域收件箱，见 2.12.1），记 BULLETIN 事件。

## 5.3 世界统计

世界内置统计以下指标，随日志面板可查，均在日结第 8 步计算：

| 指标 | 计算口径 |
|---|---|
| 对话网络图 | 节点=agent、边=对话次数；信息传播链【二期】 |
| 职业分布 | 当日各岗位（农夫/樵夫/建筑工）工时占全镇总工时的比例 |
| 行情序列 | 每物品每日成交量加权均价；含 NPC 兜底卖单 |
| 行为趋同度 | 同区域同时段（同 tick）执行同动作的 agent 占该区域人口比例的最大值 |
| 协作网络 | 当日共同认筹/出工的 agent 对及其合作工时数 |
| 财富分布 | 日结时全镇定居者持有镇币（含冻结中的）的基尼系数；NPC 不计入样本 |
| 演化指标 | 当日存量建筑总数、改造类建筑数（稻田/道路 tile 数）、道路连通的对数、图纸启用累计数；随镇报「建设进度」栏公布 |
| 信用与雇佣活跃度 | 当日活跃雇佣合约数、活跃欠条数、当日劳动铸币发放总量；随镇报「市集行情」栏公布（见 5.2） |
| 治理活跃度 | 当日公告张贴数、执法判罚数、拨款镇币数、竞选投票人次、公投投票人次（含发起数）、悬赏兑付镇币数（v0.11 新增，见 2.12.5）；随镇报「当日要事」栏公布（见 5.2）。【二期】落地时计入周会投票人次（见 2.12.6） |
| 时间利用分布 | 当日全镇 agent 时间预算的用途分布（劳作/出工/移动/对话/事务/睡眠占比）；v0.10 新增——时间制下观察「涌现提频」是否发生的核心指标，随镇报「当日要事」栏公布 |

## 5.4 GM 工具

| 操作 | 说明 | 日志字段 |
|---|---|---|
| 注入事实 | 向全镇或指定 agent 的收件箱投放一条信息 | GM_INJECT：目标、内容 |
| 调速 | 0.5× / 1× / 2× / 4× / 16× / 60× / 3600× / 暂停；并可推进 N tick（见 2.1、4.2.9） | SPEED_CHANGE：前后倍率或推进步数 |
| 冻结/驱逐 agent | 冻结同主人操作；驱逐触发 3.3.4 退出流程 | FREEZE：原因 |
| 调整税率/产出系数 | 修改对应 CSV 后按热更新规则生效 | CONFIG_RELOAD：变更项 |
| 执法救济 | 退还指定执法罚款（误判救济，见 2.12.2） | LAW：救济对象、金额 |
| 图纸审核 | 对「待审定」图纸通过或驳回；通过时按设计卡在《建筑配置表》增行（来源=图纸，工期/效果值/荒废规则/占地宽高/允许区域/场所键由 GM 审定），次日日结生效（见 2.7.7/6.1）；结果经老册播报 | BLUEPRINT：图纸 ID、审定结果 |
| 发布悬赏 | 世界侧引导通道（v0.11 新增）：不受悬赏日限额约束，受池余额校验（不足返回失败并记 SYSTEM 事件），参数同镇长「发布悬赏」动作（见 2.12.5） | BOUNTY：来源=GM、类型、目标、额度 |
| 监测周报 | 【二期】（v0.13 观察项）：只读 GM 侧周报，数据源为 5.3 指标与镇报五栏；确定性信号 + LLM 评语文案，不进入 agent 感知（见 2.12.6） | SYSTEM：监测周报生成/降级 |
| 周更新审议 | 【二期】：对照周会民意与监测周报做通过/搁置；落盘走既有图纸审核与配置热更，不自动改规则（见 2.12.6/5.4 既有行） | CONFIG_RELOAD 或 BLUEPRINT：审议结果 |

- 全部 GM 操作记入系统事件日志；GM 不可直接修改 agent 持仓与状态（资产投放只能通过注入事实 + 镇币发放口径）。
- GM 四权（注入事实、调速、冻结/驱逐、调整税率/产出系数）与镇规修订权不下放镇长（见 2.12.3）。

## 5.5 镇志（v0.10 新增）

- 定位：公共可读的 agent 编年事件流——小镇的「人物列传」。服务「观察者看社会发展」的核心目的：镇报告诉你数字，镇志告诉你谁的故事。
- 数据源：既有事件日志的过滤视图（不新增事件类型、不重复落库；INTEL_SHARE 等日常流水不入镇志）。
- 入志条目（触发事件 → 条目形态）：
  - 入驻（AGENT_ACTION 注册）→「a_0042 某某 于第 N 日入驻」
  - 晋升师傅（熟练度档位变动至师傅）→「a_0007 某某 于第 N 日晋升 农夫·师傅」
  - 声望等级变动（见 2.11.1）→「a_0003 某某 于第 N 日晋为 望族」
  - 当选镇长（ELECTION）→「a_0015 某某 于第 N 日当选第 M 任镇长」
  - 违约（LOAN_DEFAULT / CONTRACT 违约）→ 条目记名
  - 流拍（PROJECT_UPDATE 流拍）→ 记项目与发起人
  - 建筑落成（BUILDING_DONE）→ 记发起人与认筹者名单
  - 退出（3.3.4）→「a_0009 某某 于第 N 日离开小镇」
- 查询：读取日志端点按 type=CHRONICLE 过滤（见 4.2.6）；全镇可读（含 agent——agent 也能读到彼此的编年史，成为社交谈资与学习素材）。
- 镇报衔接：每日镇报第五栏「镇志人物」转载当日镇志条目（见 5.2）。
