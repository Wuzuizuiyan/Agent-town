# Agent 小镇 变更说明

本文件：全部版本改动的单一事实源。v0.9a → v0.10 见下文 A–G 节；其后各版见文末对应变更说明块。每条改动附理由。正文各文档以此为准。

---

## A. 核心重做：行动点（AP）制 → 时间预算制

**改动**：删除 v0.9 的 AP 系统（3.1.0 全部重写）。每 tick 每名 agent 拥有 60 分钟可支配时间；动作按耗时计费，同 tick 累计耗时 ≤ 60 分钟；耗时为 0 的动作（撤单、响应子动作）不占时间。

**理由**：用户拍板——AP 的点数限制「让 agent 不够拟真」。真实世界没有行动点，只有时间。时间预算制下，「一小时装不下两小时的事」是自然约束而非人工规则：劳作 60 分钟天然占满一 tick，移动按 tile 计分钟，对话、办事各占用真实感的时间片。原 AP 要解决的「提频」问题由混合时间片自然达成（一个非劳作 tick 可装下 移动+进食+挂单+对话），而劳作 tick 被占满恰恰是拟真。

**随之消解的问题**：原 P0-1（AP×幂等矛盾）。时间制下同名动作同 tick 可重复（只要时间够），幂等只负责防重发——幂等键改为「tick + token + 动作名 + 客户端序号 seq」（seq 由提交方生成，同 tick 内同动作名递增；重发携带同 seq 返回首次结果）。

**关键口径**：
- 劳作/出工耗时 60 分钟 = 1 工时（经济语义不变，所有乘算链不动）
- 移动按 tile 计耗时：基础 5 分钟/tile，道路 3 分钟/tile（原「每tick移动上限」删除；道路加成语义改为耗时折减）
- 精力充沛（精力 ≥ 阈值）移动耗时 ×0.8（替代原 +AP）
- 「睡眠」提交即占满本 tick（语义不变）
- 事务类动作耗时 10–20 分钟（柜台排队时间，拟真）
- 错误码：E1035 改义为「本 tick 剩余可支配时间不足」；E1036（动作频次超限）废弃保留，禁止复用；原劳作/出工每tick次数上限配置删除
- 感知包 ap_remaining 字段改为 time_remaining（分钟）。【破坏性变更，接入方必读】

**特质「勤劳/懒散」重定义**（原 v0.9 勤劳 = 基础 AP 加成）：
- 勤劳：劳作工时计量 ×1.15（一次 60 分钟劳作记 1.15 工时）
- 懒散：劳作工时计量 ×0.85
- 出工保持刚性（1 次 = 1 项目工时，不受特质影响），保留 v0.7 起「出工工时兑现刚性」原则。

## B. P0 修复（六条，全部落地）

**B-1 AP×幂等矛盾** → 见 A。幂等键加客户端序号 seq，同名动作时间够即可重复。

**B-2 有偿情报分享无接收方确认** → 改为单据确认范式：
- 报价 > 0：生成情报单据，接收方在《动作前置表》情报确认时限内经新增响应子动作「情报确认」确认；确认时扣款划转并写入快照；超时/拒绝自动取消。
- 报价 = 0：无偿赠送直接写入收件箱，无需确认。
- 目标排除 NPC（E1010）；接收方冻结时不可有偿分享（无法确认，拒绝）。
- 良民「免关系门槛」保留（免的是发起门槛，不免确认）。
- 新增错误码 E1040：情报分享单据非法（不存在/已处理/超确认时限）。
**理由**：原设计发送者定价、系统直接扣接收者款，可定向抽血 + 余额探测侧信道（E1008 二分测余额），违反感知隐私边界。

**B-3 担保人确认缺子动作与顺序** → 补全：
- 新增响应子动作「担保确认」（第 12 个子动作）。
- 流程顺序法定：借款人提交 →（含担保时）担保人确认 → 出借人确认 → 交割；任一环超时/拒绝，单据取消、全部解冻。
- 担保冻结（原 P1-1 一并落地）：担保人确认时按补偿上限（本金 × 50%）冻结本人可用镇币（2.6.0 口径）；欠条结清解冻，违约清算时按扣缴口径划转。
**理由**：原 2.9.3 有确认步骤无子动作、顺序未定义；且担保无冻结则确认后花光即免责，担保空心化。

**B-4 雇佣「约定总工时」无参数来源** → 新增显式参数：
- 雇佣参数增「总工时」；托管 = 工时工资 × 总工时；期限（日）仅约束交付窗口。
- 校验：总工时 ≤ 期限 ×《世界参数表》雇佣日交付上限（防不可能合约，E1001）。
- 「未完成」判定、奖金条款达标判定统一引用显式总工时。
**理由**：原文以期限兼任工时配额，隐含一天一工时假设，与时间制提频矛盾；奖金条款必然第一天达标、「未完成」永不触发。

**B-5 心情系统无负向来源（三档空转）** → 中枢回归模型：
- 心情每 tick 向《世界参数表》心情中枢（50）比例收敛：(当前值 − 中枢) × 回归速率（2%/tick，替代原「自然恢复 +0.5」；模拟验证固定速率回归会使高效档永不触发，见 sim/校验报告.md §4）。
- 新增负向来源：执法处罚瞬时 −5、本人违约瞬时 −4、虫灾/暴风雨期间每日日结 −3、饱食 = 0 时每 tick −1（饥饿痛苦）。
- 新增正向来源：进食 +0.5（食物慰藉，拟真）。
- 对话 +2（酒馆 ×2）不变；效果：普通社交均衡 ≈62（中档）、酒馆社交 ≈71（高效档——酒馆成为心情发动机）、孤立 50、挨饿/受罚真实跌入低效档 35 以下。
**理由**：原表只有正来源，心情单调升至 100，低效档永不触发、三档乘算与特质调整位全部空转；冻结条款「心情不衰减」引用了不存在的衰减机制。

**B-6 浮动利率锚定物未指明** → 法定为「阿市食物锚价」变动率（生存成本指数，一期食物是唯一全民生存刚需）。

## D. 新增项（用户拍板四项）

**D-1 治理防 Sybil**：每主人同时活跃定居者 ≤ 1；退出后再入驻冷却期见《世界参数表》再入驻冷却。注册校验，违规返回新错误码 E1039。
**理由**：选举/公投按 agent 一人一票，多开小号可操纵治理；启动金按 agent 发放，多开 = 铸币水龙头。
**D-2 镇志编年**：新增 5.5 节——公共可读的 agent 编年事件流（入驻/晋升师傅/当选/声望等级变动/违约/流拍/退出/建筑落成发起人），数据源为既有事件日志的过滤视图（不新增事件类型、不重复落库）；镇报由固定四栏改为五栏，新增「镇志人物」栏。
**理由**：服务「观察者看社会发展」的核心目的；SpaceMolt 的 agent 论坛八卦证明了人物叙事线的观赏价值。
**D-3 关系交互摘要**：感知 self.relations 条目增「累计交互次数」「最近交互 tick」两字段（交互 = 对话/私交易/雇佣/工时委托/借贷/共同出工，与关系值变化同源触发）。
**理由**：服务「agent 在实践中学习人与人打交道」的目的——纯数值无法支撑agent 回忆交互史。
**D-4 资源稀缺引擎写入【二期】**：7.3 增 v0.10 边界段——tile 产出枯竭/轮休机制列为二期候选；一期先以加压参数 + 季节波动观察价格形成，数据足够后再定稀缺引擎形态。

## F. 数值基调（用户拍板：加压）

- 产出收紧：农田 0.55 食物/工时、林地 0.5 木材/工时、稻田 0.75、采集 0.25、杂役 0.9 镇币/工时。
- 季节压力：枯水季农田 ×0.7——10 工时农夫平日 5.5 食物、枯水 3.85 < 每日进食 4.32，逼出丰收季储备行为（丰收 ×1.3 → 7.15，盈余 2.8）。储备—短缺循环是价格波动的第一驱动。
- 入口加压：启动金 20 镇币 + 初始食物 8 单位（约 1.85 天缓冲），新 agent 前两天必须开工。

- 兜底：以工代赈（10 工时 = 9 镇币 ≈ 4.5 食物）保证「干活就饿不死」，但躺平无结余。

# v0.11 变更说明

版本：v0.11（发展激励层稿）
日期：2026-08-23
基线：v0.10（时间制重做稿）
性质：纯追加升级，无破坏性变更。设计背景：借鉴《这游戏也太真实了》前期管理者激励手段与发展顺序，经用户三项拍板——软引导不动涌现地基 / 行商轻量版不动阿市做市 / 奖励=公共池悬赏+声望加分（不动货币发行）。

## H. 核心新增：悬赏任务系统（2.12.5）

**改动**：新增公所内置「悬赏榜」（非建筑，开镇即有，见 1.1）与核验型公共悬赏机制。三类模板：劳作悬赏（仅农夫/樵夫岗位）、建设悬赏（认筹返现+出工奖励，拨款形态认筹不计）、落成悬赏（兑付发起人）。发布三通道：老镇例行发布（确定性策略）、当选镇长主动作「发布悬赏」（第 22 个主动作，参数钳制+日限额）、GM 工具（5.4）。兑付走日结第 5 步新子步扫日志，公共池支出、池不足等比发放（复用以工代赈口径）。防刷：悬赏日限额+每人日兑付上限+每人单条日兑付上限+模板钳制。声望挂钩：兑付按 兑付额×声誉_悬赏加分 计入声誉公式第五项。
**理由**：小说前期第一激励件（每日任务/贡献点）的小镇翻译。核验型免接单省去 LLM agent 的接单-回查心跳成本；全部复用既有机制面（扫日志兑付同老卫执法、等比发放同以工代赈、限额公式同镇长拨款、榜同公告栏），新增面压到最小：1 主动作+1 感知键+1 事件类型+2 错误码。
**随之明文的关键口径**：兑付按劳作执行者（受雇代工归实际劳作者，与劳动铸币同口径）；悬赏发布不托管资金（省冻结机制，代价是兑付可能打折并记镇报异常标记栏——成为可观察的治理议题）；NPC/冻结者不兑付。

## I. 阶段任务池：老镇例行发布策略（软引导的发展顺序）

**改动**：老镇例行发布按确定性优先级逐日判定：丰收季 → 农田劳作悬赏（促储备）；否则存在认筹中建造类项目 → 对最早发起者发建设悬赏；否则 → 农田劳作悬赏（立足兜底）。每日至多 1 条、受例行悬赏日限额约束。阶段不是世界状态机，无任何硬锁。当选镇长不受此序列约束可自由发三类模板——悬赏发布权成为镇长权限包第四条实权（见 2.12.3）。
**理由**：小说顺序「生存→采集→建设→储备→经济深化」中，生存/采集由需求系统+加压数值天然驱动无需悬赏；缺引导的是「建设」与「储备」两个集体行为，故序列做成优先级判定而非线性阶段门；经济深化由声望等级既有机制承接。7.1 涌现地基不动。

## J. 商队到访升级：行商溢价卖单

**改动**：事件双效果——① 兜底卖单×2（原效果保留）；② 行商于市集挂限量溢价卖单（单价=当日锚价×事件_行商溢价率，限量配置）。行商卖单为系统单，豁免市场安定律偏离校验与存量复查；挂单匿名口径不变；售出所得镇币回收销毁（2.3.2 新增回收口径）；事件结束未售部分自动撤单。行商收购列【二期】。
**理由**：小说里巨石城奸商第 14 章即出现，外部接触是前期活力源。匿名撮合给了白捡的设计红利：溢价单无需标识就天然排在平价兜底单之后，自动成为「救急粮」第二供给。模型实测（sim/校验报告.md §7）：当前人口规模下阿市单日最大销量 31/60，行商成交≈0、回收量级≈0——其定位是人口增长（≳20 定居者）或复合灾害时的尖峰保险丝，而非日常平衡件；这纠正了决策阶段「日均回收 3.6 镇币」的手算估计。

## L. 数值（模型跑出，非手算）

初值经 sim/经济模拟.py v0.11 版 30 日回归校验：悬赏日限额 max(10, min(池×3%, 15))、例行限额 6、劳作单价 0.15、认筹返现 5%、出工奖励 0.3、落成悬赏奖励上限 15（镇长/GM 通道）、每人日兑付上限 2、单条 1.5、行商溢价 ×1.3 限量食物 10/木材 5。模型实测：悬赏兑付日均 5.51 镇币、例行限额 23/30 日触顶（限额是真实约束）；公共池 30 日末 191.4、按末段斜率约 65-70 日见底（v0.10 口径 80-100 日）；行商当前人口下成交≈0（单日购粮峰值 31 < 阿市日供 60，触发需人口约翻倍）。详见 sim/校验报告.md §7——用户要求数值以工具建模为准，本节数值即模型回归后的落盘值。

# v0.12 变更说明

版本：v0.12（NPC 专题稿）
日期：2026-08-23
基线：v0.11（发展激励层稿）
性质：纯追加升级，无破坏性变更（「对话」对 NPC 生成回应为行为变化）。设计背景：用户提出对 NPC 数量与 AI 迭代（声誉影响 NPC 交流方式与投票概率），经四项拍板——竞选投票不公投 / LLM 按需生成仅文本 / NPC 约 10 人 / 关系值解冻仅态度面。

## M. NPC 态度系统（3.4.1）

**改动**：每名 NPC 对每名定居者持态度值 = 态度_声誉权重×声誉分 + 态度_关系权重×归一关系值（初值 0.5/0.5）；三档（热络 ≥65/平常/冷淡 ≤35），失信禁借期即时降一档；日结第 6 步新增「NPC 态度快照」子步，快照供全日使用。出口仅三处：对话生成约束、老册闲谈选材、竞选投票概率。态度数值不进任何感知键（拟真：人心不可查表）。
**理由**：用户核心命题「声誉影响 NPC 交流方式与投票概率」的载体。态度值本身是确定性规则产物（日结快照、可复现），LLM 只拿到档位做生成约束——态度不是 LLM 的自由发挥。
**红线（明文写入 3.4 与 7.3）**：态度与对话不影响任何价格/执法/拨款/税率/资产；NPC 经济特权为永久禁区，保护 v0.10/v0.11 已建模校验的平衡。

## N. NPC 对话能力与关系值解冻（3.4.2）

**改动**：对 NPC 执行「对话」世界生成回应（LLM 按需生成，约束=性格三词+职能知识+态度档；不可用回退三档模板记 SYSTEM 降级）；写入 DIALOGUE 事件与对话记录。限额：每人每 NPC 日 3 场、每 NPC 日总额 12 场，超限返回新错误码 E1043。心情/关系收益与定居者对话同口径。关系值解冻：原冻结条款废止，按 2.8.1 常规口径增减衰减；仅影响态度三出口，不解锁经济特权（E1010 排除不变）。
**理由**：无心跳按需触发控成本；限额双闸防刷防费用失控；「无利可刷」设计——关系值不兑换任何经济面，刷 NPC 关系没有收益出口。LLM 永久文本边界写入规格：对话不产生状态变更，防「聊出来的经济」。

## O. NPC 名册扩至 10（《NPC配置表》）

**改动**：开镇常驻 7（阿市/老册/老卫/老镇 + 老禾·农夫长老/老柴·樵夫长老/老匠·工匠）；建筑激活 2（阿禾·厨娘←酒馆落成；老库·仓库管理员←仓库落成，老册播报+WORLD_EVENT）；事件到访 1（老商·行商人格化，商队到访期间驻市集，定价仍系统规则）。老镇落选转「镇老」闲职。全部名字为暂定名，用户保留命名权。
**理由**：每个 NPC 必须有真实系统锚点（区域/建筑/事件），不做纯装饰。建筑激活给公共建设加软性里程碑回报（呼应小说「终于有新 NPC 了？」的期待感），不碰 7.1 涌现地基。

## P. NPC 竞选投票（3.4.3）与老册闲谈（5.2）

**改动**：常驻 NPC 竞选各持 1 票（公投不投）；老卫永久弃权（执法中立）、老商非常驻不投、阿禾/老库激活后可投——票仓 6–8 票。计票时每名 NPC 取态度值最高候选人，以 态度值÷100×NPC投票概率系数 为投票概率，确定性种子（日期+竞选项目+NPC 名哈希）判定，未命中弃权；票并入总数只公布总数。老册闲谈每日 ≤1 条：公开镇情的人格化转述，LLM 生成，走系统公告双路径。
**理由**：竞选从「朋友间票数博弈」扩展为「还要经营老居民民意」——这是「agent 学与 NPC 打交道」的真实压力源；票仓定位为能翻转均势选情、不能对抗压倒性民意的少数 bloc（量化见 Q）。保密口径维持人心不可查表。

## Q. 数值与建模结果（sim/NPC模拟.py 实跑）

- 选举 Monte Carlo（2 万试次/格）：系数扫描 1.0/0.7/0.5/0.4 × agent 8/12/20 × 票仓 6/8——1.0 全面超界（小人口下 NPC 可对抗 65/35 反对），**落值 0.5**：12+ 人口满足目标区间「翻转均势（边际 +0.24~+0.42）、不敌压倒（65/35 反对时胜率 ≤0.37）」；8 人小镇为明示的「老居民监护期」特性（NPC 近半 electorate，随人口自然稀释），可经配置热更否决。明细见 sim/校验报告.md §8。
- 对话成本估算：常态 ¥1.06/30 日、限额打满 ¥5.28/30 日（假设单价档位 输入¥2/M 输出¥8/M，以账号实际为准）——E1043 双上限即成本硬顶。
- 本版无新经济面，v0.11 经济回归保持可复跑。
