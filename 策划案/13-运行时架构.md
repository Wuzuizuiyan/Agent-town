# 8. 运行时架构

（v0.15 新增。世界运行时尚未落仓库；本章是实现前的架构冻结。规则数值仍以第 1–7 章与 config/ 为准。）

## 8.0 拍板

- **要插拔**：一期之后每个新增机制（新动作、新建筑效果、新日结子步、新感知键、新事件类型）必须是机制插件。坏了只停该插件，不拖垮 tick / 地图 / 账本。
- **不要一切皆插件**：对照 DeepSeek Harness（dsh / Cordis）只取两条保证——**时间可组合**（卸载撤销该插件全部注册）与**空间可组合**（声明 inject，依赖未就绪则不加载）。**不**把时钟、五步管线、地图、账本精度、LLM 文本边界、NPC 经济禁区做成可卸载插件。世界是确定性模拟器，不是 agent harness。
- **不引入 dsh 依赖**：世界侧不 vendoring Cordis、不跑 `dsh`。接入的定居者 agent 可以用 dsh 或其他 harness；世界只认第 4 章 HTTP。
- **提案不等于热加载代码**：`blueprint_propose`（见 2.7.7）的主路径是配置增行（见 8.3）。效果键未注册则 GM 不得通过。镇内 agent 写插件上线仍禁止（见 7.3/2.12.6）。

## 8.1 三层

| 层 | 改什么 | 何时生效 | 谁能改 |
|---|---|---|---|
| 内核 | 物理与红线 | 发版 | 世界开发者 |
| 配置插件 | CSV 行（建筑类型、参数、开关） | 次日日结第 1 步（见 6.1） | GM；图纸审定增行 |
| 机制插件 | 代码：动作/效果/钩子/感知键 | 部署清单变更后，次日日结加载；禁止 tick 中途热加载代码 | 世界开发者发版；GM 只改清单启用/停用 |

建议目录（实现时可同构改名，职责不可合并进内核）：

```
world/
  kernel/          # 8.2
  plugins/<id>/    # 8.4，一期全部 in-tree
  profiles/        # 启用清单。不进六张 CSV，口径同 TOWN_GM_TOKEN
```

一期不设插件市场、不从网络拉代码。

## 8.2 内核（特权，不可卸载）

内核只保留世界若缺了就不再是「这个小镇」的部分：

1. 时钟与调速、tick 五步顺序、日结九步顺序（见 2.1）；插件只能在步后**追加**钩子，不能重排、不能删除内核步。
2. 64×64、地理区域、占地、移动校验、同格重叠（见 2.2）。
3. 账本：食物/木材整数向下取整、镇币按「镇币小数位」量化（见 2.3）；冻结/解冻原语。
4. 时间预算调度与动作分发：未知 `action` → E1001；插件未加载 = 该动作不存在。
5. HTTP `/v1` 信封、鉴权、幂等键、webhook 签名（见第 4 章）。
6. 事件日志原语与 5.1 schema。
7. 配置加载与非法行保留旧值（见 6.1）。
8. 插件总线：inject、register、unload（见 8.4）。
9. 红线执法：LLM 只出文本、NPC 不持有可交易物资、确定性 RNG。

`move` 属内核。`work` / `eat` / `sleep` 属生存插件（见 8.7）。内核不得出现具体岗位产出公式、市集撮合、认筹状态机。

## 8.3 配置插件 = 图纸提案主路径

《建筑配置表》增行且「效果键」已有机制插件实现时：**零新代码**，次日日结生效。这是 2.7.7 的默认出口，也是 7.1「无需改代码改规则」的实现口径。

审定规则：

- GM 通过图纸必须填写占地宽高、允许区域、场所键、**效果键**（见 2.7.7）。
- 效果键必须是当前已加载机制插件登记过的 kind；未登记 → 驳回，不得写成「已启用」。
- 场所键标识该建筑类型的场所（可新建，如以后的 `apartment`）；效果键可复用（公寓可复用 `house_bind`）。
- 「效果值」列供人与镇报阅读。一期插件读数走既有配置行（如住宅绑定容量、田圃扩建加成上限），不解析效果值里的自然语言或公式。
- 效果说明无法映射到已有效果键（例如要新资源、新动作、改日结顺序）→ 不走配置增行；记入 7.3 观察项，由世界外发版提供新机制插件后再审定。

开镇水井无建筑配置行，由内核按初始水井坐标放置 1×1 场所 `well`。

## 8.4 机制插件契约

每个插件：`plugin_id`（英文蛇形）、`inject` 列表、`apply(ctx)`、卸载时由总线撤销 `apply` 内全部注册。

内核提供的 inject 键（缺一则该插件不加载，记 SETTLE_ERROR）：

| 键 | 能力 |
|---|---|
| clock | 当前 tick/日、调速只读 |
| map | 区域、占地、场所、可进入 |
| ledger | 食物/木材/镇币/凭证增减与冻结 |
| agents | 定居者与 NPC 只读定位；写需求/背包走 ledger+needs |
| needs | 饱食/精力/心情（仅定居者） |
| perception | 注册感知键 |
| log | 写 5.1 事件 |
| rng | 确定性随机：种子 = 世界种子 + tick + plugin_id；禁止墙钟与额外熵 |
| config | 读六张 CSV 已加载快照 |
| llm | 仅 `complete_text(constraints) → str`；不可返回状态补丁 |

`apply(ctx)` 允许的注册（空间可组合：只通过 ctx，禁止 import 其他插件私有实现）：

| 方法 | 用途 |
|---|---|
| `ctx.actions.register(api_name, handler)` | 3.1 / 3.1.3 动作 |
| `ctx.effects.register(kind, handler)` | 建筑效果键 |
| `ctx.hooks.tick_after(step, fn)` | 五步之一结束后追加 |
| `ctx.hooks.daily_after(step, fn)` | 日结九步之一结束后追加 |
| `ctx.perception.register(key, scope, fn)` | 感知键；scope=self/region/inbox |
| `ctx.events.allow(type)` | 该插件可写的事件类型 |
| `ctx.npc.register(npc_id, behavior)` | NPC 行为；behavior 不得改账本（阿市补单走 market 插件的系统供给） |

时间可组合（卸载）：

- 总线记录 `apply` 期间每一次 register，卸载按逆序撤销。
- 该插件的 `action` 此后 E1001。
- 仅由该插件提供的效果键：已落成建筑占地保留、可进入，效果变为惰性（无加成、无解锁）。
- 进行中单据：插件可声明 `cancel_on_unload`；默认按 3.3.4 同类撤销（解冻、不记违约）。
- **不回放历史 tick**。世界只向前停用，不做 dsh 会话内的时空倒带。
- 卸载与启用只在日结第 1 步、配置加载之后执行；tick 中途禁止。

故障隔离：单个插件钩子或 handler 抛错 → 回滚**该条动作**副作用（与 2.1.1 第 2 步单条失败同口径），记 SETTLE_ERROR / SYSTEM，**不中止**内核后续步与其他插件。同一插件同 tick 连续失败达实现上限（建议 8 次，不进 CSV）则本 tick 跳过该插件剩余钩子。

确定性：tick 路径禁止网络 IO（webhook 由内核在本 tick 全部结算后发出）。禁止读墙钟做规则分支。

## 8.5 效果键清单（一期）

内置 11 种建筑的效果键（建筑配置表「效果键」列；场所键仍表示场所身份）：

| 建筑 | 场所键 | 效果键 | 提供插件 |
|---|---|---|---|
| 住宅 | house | house_bind | construction |
| 仓库 | warehouse | warehouse | construction |
| 酒馆 | tavern | talk_mood_mul | social |
| 公告栏 | bulletin | unlock_bulletin | governance |
| 议事厅 | hall | unlock_plebiscite | governance |
| 田圃扩建 | field_upgrade | farm_labor_mul | construction |
| 水井扩建 | well_upgrade | unlock_forest_tiles | construction |
| 道路 | road | road | construction |
| 稻田 | paddy | owner_paddy | construction |
| 荒地开垦 | farm_plot | owner_farm_plot | construction |
| 密林开垦 | forest_plot | owner_forest_plot | construction |

图纸复用效果键时，数值口径与该效果键的内置配置相同（例如 `house_bind` 一律读住宅绑定容量）。要不同数值或新效果，先发版新插件或新配置行，再审定。

| social | talk、心情对话收益、酒馆乘算依赖 talk_mood_mul |

profile 示例（部署文件，非 CSV）：第一枪 = survival + market；完整一期 = 上表全部。未列入的插件视为未加载。

## 8.7 第一枪（相对 7.9）

在 7.9 的机制顺序之前，必须先有：内核（8.2）+ 插件总线（8.4）+ profile。生存与市集以插件形式挂上，禁止把产出公式或撮合写进 `kernel/`。

其后仍按 7.9：地图与 move → survival → market → 拉模式接入 → 日志 → warehouse/道路 → 项目占地 → 其余插件。

## 8.8 明确不做

- 把 tick 主循环、账本精度、红线做成插件。
- 世界进程内嵌 dsh / Cordis，或让定居者 agent 向世界热挂代码。
- 投票通过或图纸待审定自动 `apply` 未发版插件。
- 插件 tick 中途加载、卸载、从 URL 安装。
- 效果目录自动从效果说明填效果键或效果值（仍 GM 审定，见 7.3）。
- 一期 HTTP 增 `POST /v1/gm/plugin`（启停走部署清单；该端点【二期】）。
