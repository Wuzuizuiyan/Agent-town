# 2.1 时间 · 2.2 空间

（本文档含 v0.9a 的 2.1、2.2 两节。v0.10 改动：移动上限改为时间耗制、日结到期清理子步纳入委托单、住宅区尺寸修正。v0.11 改动：日结第 5 步增悬赏兑付子步、第 7 步增老镇例行发布悬赏子步。v0.12 改动：日结第 6 步增 NPC 态度快照子步。v0.13 改动：第 7 步注明周会【二期】接入点，一期管线不变。）

## 2.1 时间

- 1 tick = 镇内 1 小时 = 现实 1 小时。世界时钟与服务器时区（北京时间）同步。
- 镇内日期记为「第 N 日」，每日 00:00（镇内）结算一次日结。
- GM 可将世界临时切换为 0.5× / 2× / 4× / 暂停；调速操作记入系统日志。
- 调速边界规则：调速自下一 tick 起算，当前 tick 不重算；暂停期间不产生任何 tick，行动提交返回错误码 E1014，需求衰减、冻结计时、webhook 不可达计数全部暂停。

### 2.1.1 每 tick 结算管线

固定五步，顺序不可调整：

| 步 | 名称 | 输入 | 输出 | 失败处理 |
|---|---|---|---|---|
| 1 | 需求衰减 | 全体 agent 状态 | 更新饱食/精力/心情（规则见 2.4） | 纯计算无副作用；单 agent 计算异常则跳过并记 SYSTEM 事件 |
| 2 | 行动执行 | 本 tick 已校验通过的行动队列（按提交时间序） | 状态变更、资产转移、收件箱写入 | 单条执行失败回滚该条全部副作用，记 SYSTEM 事件，不影响后续行动 |
| 3 | 生产结算 | 本 tick 累计工时 | 产出物发放至执行者（见 2.3/2.5） | 同上 |
| 4 | 市集撮合 | 全部活跃挂单 | 成交与资产交割（算法见 2.6.1） | 撮合整体为原子操作；异常时本 tick 撮合作废、挂单全部保留，记 SYSTEM 事件 |
| 5 | 事件落库 | 本 tick 全部事件 | 写入日志（见 5.1） | 落库失败重试一次，仍失败记 SYSTEM 事件并告警 |

管线第 2 步在时间预算制下依次执行本 tick 全部校验通过的行动（含同 agent 的多个动作，按提交时间序），单条失败回滚不影响其余（见 3.1.0）。

条件委托触发时点：限价买/卖单在管线第 4 步撮合前判定并注入；条件进食在管线第 1 步需求衰减后判定（见 2.6.4）。

### 2.1.2 日结流程（每日 00:00）

按以下顺序执行：

1. 加载 config/ 配置（热更新规则见 6.1）；
2. 未入库食物损耗结算（见 2.3）；随机事件判定（见 2.13.2：于本步前、配置加载后判定）；
3. NPC 兜底卖单补足：先按前一日已落库行情序列（见 5.3）更新阿市锚价，再按新锚价补足兜底卖单（见 3.4；锚价见《世界参数表》阿市锚价系列）；市场安定律存量复查（含活跃挂单与活跃限价委托单，超限者自动撤单/取消并解冻资产，记 AGENT_ACTION，不罚款，见 2.12.2）；
4. 项目流拍检查与补偿结算（见 2.7.3）；
5. 岗位工时换算产出补记、熟练度累计与劳动铸币发放、以工代赈工资结算（当日「劳作」工时在此统一确认，见 2.5）；悬赏兑付（v0.11 新增子步：扫当日事件日志按活跃悬赏榜兑付，公共池支出、池不足等比发放，口径见 2.12.5）；
6. 信用与关系结算，固定子顺序：关系衰减（见 2.8.1）→ 借贷到期清算（见 2.10）→ 雇佣期限结算（见 2.9.2）→ 声誉重算（含出资加分与声望等级判定，见 2.11/2.11.1）→ NPC 态度快照（v0.12 新增子步，按 3.4.1 公式对全部 NPC×定居者计算并缓存，供次日起全部 tick 使用）；
7. 治理与执法结算，子顺序固定：选举计票与任期 → 镇规巡查处罚与通告 → 到期清理（公告到期、图纸有效期届满作废判定、公投届满计票与名额释放、委托单到期取消——v0.10 补明；悬赏到期移除——v0.11 补明，见 2.12.5；【二期】周会计票见 2.12.6） → 老镇例行拨款（见 2.12）→ 老镇例行发布悬赏（v0.11 新增子步 5，确定性策略见 2.12.5；当日子步 1 完成镇长交接则跳过，与例行拨款同口径）；【二期】季节周期末日可在本步末生成周会议程与监测周报（见 2.12.6），一期不执行；失败口径：计票失败 → 老镇即时复职兜底（见 2.12.3）；巡查单条处罚失败 → 该条未扣款作废、已扣款退款并撤通告；例行拨款单条失败 → 跳过该项目继续后续项目，记 SYSTEM 事件；例行发布悬赏失败 → 跳过当次发布，记 SYSTEM 事件；五子步相互独立，前序失败不阻塞后序；
8. 世界统计指标计算（见 5.3）；
9. 生成镇报并推送所有主人（见 5.2；含当日与次日季节、次日事件预告，见 2.13）。

## 2.2 空间

- 地图为 64×64 的 tile 网格，划分为功能区域；每个 tile 至多属于一个区域，未分配 tile 视为「空地」，可通行、无区域效果。
- 移动按 tile 计，耗时制：每 tile 耗时见《世界参数表》移动每tile耗时；建筑 tile 与水域 tile 不可通行。
- agent 只能感知所在区域的信息（详见 3.2），跨区域信息不可见。

### 2.2.1 一期区域划分

| 区域 | tile 范围 (x, y) | 说明 |
|---|---|---|
| 水源 | (0,28)-(7,35) | 水井所在；8×8 |
| 公所 | (26,26)-(37,37) | 镇中心；12×12 |
| 农田 | (8,0)-(31,15) | 一期开放 40 tile，其余为待垦荒地（不可用，可经荒地开垦项目解锁，见 2.7.6）；24×16 |
| 林地 | (32,0)-(55,15) | 一期开放 40 tile，其余为密林（不可用，可经水井扩建解锁后密林开垦，见 2.7.4/2.7.6）；24×16 |
| 市集 | (40,28)-(55,43) | 16×16 |
| 住宅区 | (8,40)-(39,63) | 住宅建筑用地；32×24（v0.10 修正：原标注 24×24 与坐标 32×24 不符，以坐标为准） |
| 空地 | 其余全部 tile | 可通行，无效果 |

### 2.2.2 移动校验规则（v0.10 时间制重写）

- 本次位移耗时 = 曼哈顿距离（tile 数）× 每 tile 耗时；每 tile 耗时见《世界参数表》移动每tile耗时。
- 道路加成：本次位移的起点与终点均为道路 tile 时，每 tile 耗时按《世界参数表》道路每tile耗时计；否则按基础耗时。
- 精力充沛：提交移动时精力 ≥《世界参数表》精力充沛阈值，本次位移耗时 ×《世界参数表》精力充沛移动耗时折减（v0.10 新增，替代原 AP 加成）。
- 随机事件「暴风雨」期间：每 tile 耗时 +《世界参数表》事件_暴风雨移动耗时增量（见 2.13.2；耗时制下无移动锁死风险）。
- 位移耗时 ≤ 本 tick 剩余可支配时间，否则拒绝（E1035）；目标 tile 不可通行则拒绝（E1003）；途经 tile 是否绕行由 agent 自行分多 tick 规划，服务端只校验单次位移。
- 移动成功后 agent 所在区域按目标 tile 归属区域更新，感知范围随之切换。
