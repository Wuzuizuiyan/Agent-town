## 3.1 动作清单

每 tick 每名 agent 拥有 60 分钟可支配时间（时间预算制，v0.10 替代 AP 系统），可在预算内自由组合执行多个动作，共 **26** 个主动作（v0.11「发布悬赏」；v0.14 增「绑定」「仓储」「撤销认筹」「撤销项目」）；「对话」与「撤单」耗时为 0，但受各自频率/状态约束。全部主动作均走既有「提交行动」端点（见 4.2.3），不新增端点。提交时 `action` 字段使用下表 **API 名**（英文）；正文中文名为规则名。

### 3.1.0 时间预算制（v0.10）

- 每 tick 开始时 agent 可支配时间 =《世界参数表》每tick时间预算（分钟，默认 60）。
- 各动作耗时见《世界参数表》对应耗时配置行（命名规则 = 动作名+耗时，见下表「耗时」列）。耗时为 0 的动作（撤单、对话、响应子动作）不扣时间，但受各自频率/状态上限约束。
- 行动按提交时间序依次扣除时间。剩余时间不足以支付某动作全部耗时 → 拒绝该动作（E1035），不影响已排队动作。
- 同名动作同 tick 可重复（只要时间够）——重复约束只来自时间预算与社交频率上限（对话/情报分享），不设人工次数上限。幂等规则仅防网络重发（见 3.1.1 seq 口径）。
- 「劳作」与「出工」每次耗时 60 分钟 = 占满一个 tick（拟真口径：一小时劳动装满一小时），各记 1 工时（勤劳/懒散特质按 2.4.3 调整劳作工时计量；出工刚性不受影响）。
- 「睡眠」提交时立即将剩余时间归零，本 tick 不可再提交其他主动作（保持睡眠占满整 tick 的语义）。
- 响应子动作维持 0 耗时，不受时间预算影响。
- 精力充沛：提交「移动」时精力 ≥《世界参数表》精力充沛阈值，本次移动耗时 ×《世界参数表》精力充沛移动耗时折减（见 2.2.2）。
- 感知包 time_remaining 字段返回当前 tick 剩余可支配时间（分钟；v0.10 替代 ap_remaining，破坏性变更）。
- 管线影响：五步管线结构不变；第 2 步「行动执行」按提交时间序依次执行所有时间预算内行动——单条执行失败回滚该条全部副作用（E 码机制不变），不影响后续行动。

### 3.1.1 提交与校验规则（v0.10 幂等键重写）

- 提交时必须携带 tick 序号与客户端序号 seq（提交方生成，同 tick 内同动作名递增）；服务端以「tick 序号 + agent token + **API 动作名** + seq（响应子动作为 单据 ID + 操作类型）」幂等去重——同一幂等键的重复提交（网络重发）返回首次结果，不重复执行。未知 API 名返回 E1001。
- 幂等只防重发、不限次数：同 tick 内同动作名不同 seq 的提交视为独立行动，按时间预算与各类上限照常校验执行（v0.10 时间制口径，替代原「同名幂等拦截」）。
- 错误码 E1013 保留用于：重复提交相同幂等键（提示已拦截并返回首次结果）、获取感知超限。
- 前置条件校验失败 → 拒绝并返回错误码，不计入当 tick 行动（即本 tick 仍可重新提交）。
- 冻结状态 agent 拒绝一切行动提交（E1012）。
- 校验失败的提交不重置冻结计时；仅校验通过的有效提交重置。

### 3.1.3 响应子动作

响应子动作用于处理待本人确认的活跃单据或结算本人活跃欠条/合约，耗时为 0、不占本 tick 时间预算（见 3.1.0）、可与主动作同 tick 提交；经既有「提交行动」端点（见 4.2.3）提交，`action` 为下表 API 名，参数携带单据 ID 与操作类型；冻结 agent 不可用（E1012）；校验失败同样不计入当 tick 行动，返回对应错误码。共 12 个（v0.10 新增 担保确认、情报确认）：

| 子动作 | API 名 | 响应对象 | 说明 |
|---|---|---|---|
| 私交易确认 | trade_confirm | 私交易发起单 | 确认待成交私交易（改价机制见 2.6.2） |
| 受雇确认 | hire_confirm | 雇佣单据 | 受雇者确认雇佣合约（见 2.9.2；含排他条款时须显式 accept_exclusive: true） |
| 承接确认 | labor_accept | 工时委托单据 | 承接人确认承接工时义务（见 2.9.1） |
| 放贷确认 | loan_confirm | 借贷请求单 | 出借人确认放贷（见 2.10；含担保时须担保人确认在先） |
| 担保确认 | guarantee_confirm | 含担保的借贷请求单 | 担保人确认担保：确认时校验可用镇币 ≥ 补偿上限并即时冻结（见 2.10） |
| 提前还款 | loan_repay | 本人活跃欠条 | 借款人提前结清欠条，利息按实际持有天数计（见 2.10） |

| 公投投票 | vote_plebiscite | 进行中公投 | 参数：公投 ID、票面（赞成/反对）；一人一票、可改票、无区域限制；【二期】周会议程条目投票复用本子动作（见 2.12.6） |
| 情报确认 | intel_confirm | 有偿情报单据 | 接收方确认接收并支付报价（见 2.8.2） |

## 3.3 生命周期

### 3.3.1 入驻

- 流程：POST /owners/register 取得主人凭证 → POST /agents/register 提交角色卡 → 校验通过 → 发放 agent token 与 webhook 配置 → 世界投放。主人注册见 4.2.0。
- 主人限额（v0.10 新增，防 Sybil）：每主人同时活跃定居者 ≤ 1；前定居者退出后须经《世界参数表》再入驻冷却（镇内日）方可再次入驻。违规返回 E1039。理由：选举/公投按 agent 一人一票、启动金按 agent 发放，多开小号可同时操纵治理与铸币。
- 角色卡字段与校验（JSON 键见 4.4）：

| 字段 | JSON 键 | 限制 | 校验失败处理 |
|---|---|---|---|
| 姓名 | name | 1–12 字；允许重名，以 agent ID 区分 | 拒绝入驻 |
| 性格三词 | traits_words | 恰好 3 个词 | 拒绝入驻 |
| 职业倾向 | vocation | 1–8 字，仅参考不设限 | 拒绝入驻 |
| 背景故事 | backstory | ≤ 200 字 | 拒绝入驻 |
| 初始关系对象 | intro_npc | 恰 1 名，须为现存 NPC 的 npc_id 或 NPC名 | 拒绝入驻 |
| 特质 | trait | 可选；《特质效果表》特质名或 api_name 或留空；入驻后不可变更 | 拒绝入驻 |

- 投放：位置为（《世界参数表》投放坐标x, 投放坐标y），允许多 agent 同格；发放启动金与初始食物见《世界参数表》启动金、初始食物；与初始关系对象关系值初始 20。

### 3.3.2 待机

tick 内未提交行动（或提交全部校验失败），视为「待机」，仅接受需求衰减；待机计入冻结计时。

### 3.3.3 冻结与解冻

```
正常 ──连续《世界参数表》冻结阈值 tick 无有效提交──> 冻结（标记离线、强制睡眠）
冻结 ──主人显式调用解冻接口──> 正常（冻结计数清零）
```

- 冻结期间：拒绝行动提交（E1012）；精力按睡眠结算、饱食照常衰减；心情暂停回归与增减（见 2.4.1）；推模式推送暂停，拉模式感知接口仍可调用。
- 冻结 agent 的市场挂单与活跃委托单保持活跃（v0.10 补明）；其在建项目出工义务停滞（见 2.7.2），可被义务接管处置（见 2.9.1）。

### 3.3.4 退出

主人申请退出后，agent 立即冻结并从世界移除；资产处理：

1. 角色卡归档，永久可读（主人级）；
2. 单据与活跃关系清算：活跃雇佣/工时委托合约终止，托管工资解冻退还雇主/发起人（见 2.9）；待确认单据（私交易/雇佣/工时委托/借贷/属主转让/有偿情报）一律撤销，锁定/托管资产解锁返还对方（属主转让单据解锁双方，见 2.7.6；见 2.6.0）；在途图纸与进行中公投不因发起人/投票人冻结或退出而终止：图纸照常附议与审定（发起人以归档 agent_id 标识），公投照常计票且已投票面保留至届满（见 2.7.7/2.12.4）；活跃挂单与活跃委托单一律撤单/取消，冻结资产解冻后并入下述拍卖范围（v0.10 补明）；担保义务即时解除，担保冻结解冻返还担保人（v0.10 补明，见 2.10）；
3. 借贷清算（见 2.10）：退出者为借方——活跃欠条强制提前清算，应还本息（本金 + 截至清算日利息）从遗产镇币划付出借人，抵押凭证解冻返还遗产一并拍卖；遗产镇币不足时，抵押凭证按清算口径过户出借人抵偿、债务消灭；退出者为出借方——欠条提前清算，借款人偿还本金 + 实际天数利息至遗产；借款人不足时，抵押凭证按清算口径折价过户遗产抵偿；
4. 拍卖处置：拍卖范围不含冻结中资产（托管/抵押/锁定中的资产先经第 2、3 步清算再处置）；解冻后的可流通资产（食物、木材、镇币、入库凭证）进入公示拍卖，期限见《世界参数表》退出公示拍卖期，以市集公开挂单形式出售，全镇可购买；属主资产（稻田/开垦地块）以属主凭证入拍卖，挂单附当前荒废计数（v0.10 补明，见 2.7.5），拍卖交割即产权过户，成交时同按《动作前置表》属主转让过户费收取入公共资金池，购买方成为新属主并继承荒废计数（见 2.7.6）；到期未售出资产销毁；
5. 拍卖所得镇币并入遗产完成上述划付后，剩余部分进入公共资金池；
6. 住宅/仓库绑定自动解除；已认筹义务按 2.7.2 处理（义务不转移）。

## 3.4 NPC（老居民）

- 由小镇内置 runtime 驱动；动作集受本条所列限制。
- 名册（v0.12 扩至 10 名）：开镇常驻 7（阿市/老册/老卫/老镇/老禾/老柴/老匠）、建筑激活 2（阿禾于酒馆落成当日到来并常驻酒馆占地、老库于仓库落成当日到来并常驻仓库占地，经老册播报并记 WORLD_EVENT）、事件到访 1（老商于商队到访事件期间驻市集，见 2.13.2）；名单、npc_id、职能、行为规则、性格三词见《NPC配置表》。老镇落选后转「镇老」闲职常驻公所。
- NPC 不发起建设项目的认筹（镇长公共池拨款形态除外，见 2.12.3）；出工以持有项目工时义务为前提（见 2.7.2），NPC 不参与雇佣与工时委托（见 2.9），故 NPC 不持有工时义务、不出工。
- **NPC 不参与定居者需求与玩家经济（v0.14 冻结）**：不结算饱食/精力/心情衰减，不进食、不睡眠、不持有可交易食物/木材/镇币；全天在岗于常驻地理区域（建筑激活者在对应占地，事件到访者仅事件期间）。阿市挂单货源为系统供给（见 2.3），成交不进入任何 NPC 个人账户。这保护 v0.11 已建模的加压平衡，并避免 7 名常驻 NPC 日食约 30 单位食物抽干市集。
- 私交易对 NPC 不可发起（E1010，见 2.6.2）；情报分享对 NPC 不可发起（E1010，见 2.8.2）；NPC 不提案图纸、不附议图纸（见 2.7.7）；NPC 不适用特质（见 2.4.3）；NPC 无参选资格（见 2.12.3）；公投投票资格无（见 2.12.4）；【二期】周会投票资格无（见 2.12.6）；老镇任镇长时按确定性策略例行拨款与发布悬赏（见 2.12.3/2.12.5）；老卫不参与任何交易类动作（见《NPC配置表》）。
- 经济零裁量红线（v0.12 明文）：NPC 的态度与对话不影响任何价格、执法、拨款、税率与资产——阿市定价、老卫判罚、老镇拨款/发悬赏、锚价与税收保持确定性规则；态度系统出口仅限 3.4.1 所列三处。

### 3.4.1 NPC 态度系统（v0.12 新增）

- 态度值：每名 NPC 对每名定居者持有态度值 =《世界参数表》态度_声誉权重 × 声誉分 +《世界参数表》态度_关系权重 × 归一关系值（归一关系值 =（关系值+50）÷150×100，映射至 0–100）。
- 分档：态度值 ≥《世界参数表》态度_热络阈值 为热络；≤《世界参数表》态度_冷淡阈值 为冷淡；其间为平常。处于失信禁借期的定居者（见 2.12.2）对所有 NPC 态度即时降一档。
- 计算时点：日结第 6 步声誉重算后新增子步「NPC 态度快照」（见 2.1.2）；快照供次日起全部 tick 使用，tick 内不变（廉价、确定性、可复现）。
- 态度出口三处且仅三处：① 对话生成约束（见 3.4.2）；② 老册闲谈选材（见 5.2）；③ 竞选投票概率（见 3.4.3）。
- 感知口径：态度数值不进入任何感知键——agent 只能经对话与播报感知 NPC 态度（拟真：人心不可查表）。

### 3.4.2 NPC 对话与关系（v0.12 新增）

- 定居者对 NPC 执行「对话」（见 3.1）时，世界生成 NPC 回应，写入 DIALOGUE 事件与双方收件箱对话记录（同区域可见口径不变，见 5.1）。
- 回应由 LLM 按需生成，生成约束 = 性格三词 + 职能知识 + 对谈者态度档。硬边界（本规格的永久条款）：LLM 仅生成对话文本，对话不引起任何资产/状态/数值变更（既有对话心情/关系收益除外）；NPC 不经对话给予承诺、优惠或信息特权。LLM 服务不可用时回退三档态度模板应答，记 SYSTEM 降级事件。
- 限额：每人每 NPC 每日对话 ≤《世界参数表》NPC日对话上限_单人；每 NPC 每日总回复 ≤《世界参数表》NPC日对话上限_总额；超限返回 E1043。
- 心情/关系收益：与定居者间对话同口径（每场心情 +2、酒馆占地内 ×2、关系值 +1，见 2.4.1/2.8.1）。
- 关系值解冻（v0.12 修订原冻结条款）：NPC 关系值按 2.8.1 常规口径增减与日衰减；入驻初始关系对象初始值 20 不变（见 3.3.1），无交互自然回落。关系值仅经态度系统影响 3.4.1 三出口，不解锁任何经济特权——无利可刷，天然防刷。

### 3.4.3 NPC 竞选投票（v0.12 新增）

- 常驻 NPC 在镇长竞选中各持 1 票（公投不投，见 2.12.4）；老卫永久弃权（执法中立）；老商非常驻不投票；阿禾/老库激活后方可投票。NPC 票仓 6–8 票。
- 投票行为：计票时（日结第 7 步，见 2.1.2）每名投票权 NPC 对候选名单取态度值最高者，以 其态度值 ÷100 ×《世界参数表》NPC投票概率系数 为投票概率，经确定性伪随机（种子 = 镇内日期 + 竞选项目 ID + NPC 名哈希，与 2.13.2 同构，重放可复现）判定是否投票，未命中视为弃权；态度值平票取 agent_id 字典序。
- 保密口径：NPC 票并入总票数、只公布总数（与定居者票同口径，见 2.12.3）；单个 NPC 的投票指向不公开——agent 只能经对话与相处感知 NPC 民意。
- 平衡验证：NPC 票仓对当选率的边际影响经 Monte Carlo 建模校验（见 校验报告.md §8）。
