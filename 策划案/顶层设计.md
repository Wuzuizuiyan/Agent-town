# 顶层设计

2026-08-26 从零重建。旧策划案（v0.15 及以前）归档于 归档/v0.15/，仅作素材库。
本文只写已确认的方向层结论；未定项集中在文末。

## 定位

- 作品本体是「世界」：搭建一个有人真正在活的小镇世界，它就是作品，不是给 agent 用的平台。
- 唯一受众是观测者：没有「玩家」。你与朋友们都是观众；朋友接入（带自己的 agent 进场）是最后才考虑的事，先验证游戏本身。
- 观测的「值了」：涌现惊喜——你以为居民会用常规方式解决问题，结果它们用了你没想到的新颖方法。
- 世界观底：借《这游戏也太真实了》的核心前提——废土拓居、居民是真实的、发展顺序——其余魔改成自己的。
- 规则哲学：涌现 = 最少的、可以有机组合的规则。参照 Minecraft：极少的规则，深不可测的组合。只提供基础接口，不写制度——雇佣、货币、市场、组织、公告栏、镇长，全部由居民自己长出来。

## 世界形态

- 空间：连续的 x/z 平面（非格子），地面层无限大；y 轴叠层——避难所地下一层/地下二层、房子楼层、矿洞等，每层是独立的 x/z 地图，层间靠电梯、楼梯等连接点通行。
- 时间：连续流动，游戏内一天 = 现实一天（1:1）。不是 tick 制。
- 移动：连续。小人真的从 A 走到 B，观测者能看到全过程，不是瞬移。
- 反馈：事件式。居民说「去 B 地」，世界用连续时间带他去；到了，告诉他「到了」；路上遇到事，把事件递给他处置。事件是离散的，居民处理得过来；世界的流是连续的。
- 生理：连续发生（如饥饿逐渐增长，越过阈值成为事件）。

## 居民

- 内置 AI 居民：世界开张第一天就是 AI 在活，没有脚本 NPC 过渡期。
- 多样性：游戏内自带居民给不同的基础设定，让他们拥有差异；将来接入的 agent 各有性格。
- 地形生成：待研究（地面无限大的前提）。

## 发展弧（开局与演化）

居民从避难所出来，面临即将到来的寒冷、缺水缺电缺食物，需要求生：砍树、狩猎，研究出如何点火、如何做食物。然后分工合作，建起外面的房子，每天为自己、为集体生产。工具不够方便了，研究怎么炼铁，升级装备。组织大了、之前的沟通方式不够高效了，发明公告栏，自己推举产生镇长。学会交易、合作。

脊柱：问题 → 研究 → 能力/制度 → 新问题 → 再研究。社会发展的每一步，都是居民被具体问题逼出来、自己想出办法攻克的。发明史本身就是社会发展，就是观测者的「值了」。

## 周目制

没有终局。但寒冷扛不过去 = 游戏结束，开启下一周目。

## 机制

- 世界架构：插件式（dsh 风格），功能可插拔。
- 配方管道（即时）：居民根据自己已有的东西和自己的知识制定配方 → 立即送到你面前审概念（该不该存在）→ 概念过，审核 AI 给出它认为合适的数值（必须有推导链：现实映射或数值模型，不能凭感觉给）→ 数值送你审 → 你同意后上线，居民研究成功。
- 拒绝有戏：任何一步没过，世界下发失败事件（爆炸、研究失败、飞机飞不起来）——拒绝成为世界内真实发生的一次失败尝试。
- 功能管道（周更）：世界还没有的新功能（如公告栏）→ 新建模块 → 下一次周更新上线；游戏内这一周为施工中。
- 观测者角色：纯观测 + 两道闸（概念闸、数值闸）。日常不干预世界运转；发展类事项过闸，不满足前提就打回。

## 观测

- 形态：实时俯视画面 + 叙事编年（发明史等记录），两者都有。
- 朋友们将来在网站上看，与观测者一样；进场时间不急。

## 待定与待研究

- 居民思考运行时（何时想、想多快、成本）——技术研究题
- 地形生成——研究题
- 配方数值的推导依据（现实映射的锚：世界基本量纲）——待解决
- 开局人数、携带物、避难所由来——后定
- 周目细节（跨周目保留什么）——后定
- 朋友进场时间与角色——后定
