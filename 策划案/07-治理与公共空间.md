# 2.12 治理与公共空间

（本文档含 v0.9a 的 2.12 全节。v0.10 改动：存量复查覆盖委托单的交叉引用、镇志衔接，其余规则不变。v0.11 改动：新增 2.12.5 悬赏任务。v0.12 改动：竞选接入 NPC 态度投票（3.4.3 衔接）。）

## 2.12.1 公告栏

- 公告栏为建造类公共建筑（认筹制，条目见《建筑配置表》）；落成后解锁「张贴公告」主动作与 bulletin_board 感知键（见 3.2）。
- 张贴公告：主动作，参数：内容；前置：公告栏已落成且 agent 位于其区域；当日张贴数未超《动作前置表》公告每日张贴上限；内容长度未超《动作前置表》公告内容长度上限；按《世界参数表》公告张贴费缴费入池。违规返回 E1024。
- 存储：公告容量见《动作前置表》公告板容量上限，保留期见《世界参数表》公告保留期；超限按先进先出于日结第 7 步「到期清理」子步清理（见 2.1.2）；张贴即时触发先进先出：容量满时踢出最旧的非系统公告腾位，被踢公告不退张贴费。
- 系统公告豁免：世界侧生成的公告（执法通告、竞选结果等）免费、不占容量、不受保留期约束。
- 公告栏未建成：全镇无公共公告载体，执法通告与竞选播报降级为收件箱通道（见 2.12.2/2.12.3）。

## 2.12.2 镇规与执法

镇规固定 4 条（GM 立法），全部机制可判定，判定口径均引用配置项：

| 镇规 | 类型 | 判定口径 | 处置 |
|---|---|---|---|
| 市场安定律 | 预防型 | 挂单单价偏离当日阿市锚价（偏离 = |单价 − 锚价| ÷ 锚价，锚价见 3.4）>《世界参数表》挂单价格偏离上限 | 提交时拒单并记 AGENT_ACTION 拒绝原因；存量复查见下条；不罚款 |
| 失信律 | 判罚型 | LOAN_DEFAULT 事件发生 | 罚款《世界参数表》执法罚款_失信入池 + 进入《世界参数表》失信禁借期（期内发起借贷返回 E1030）+ 通缉通告 |
| 雇佣守信律 | 判罚型 | CONTRACT「违约」形态事件（合约期内提前解约产生；自然到期不产生违约形态事件，见 2.9.2） | 罚款《世界参数表》执法罚款_雇佣违约入池 + 通告 |
| 流拍责任律 | 判罚型 | PROJECT_UPDATE「流拍」且阶段=施工中 | 发起人罚款《世界参数表》执法罚款_施工流拍入池 + 通告 |

- 执法 NPC 老卫（见《NPC配置表》）：每日日结第 7 步按《世界参数表》执法巡查频率匹配前一日事件日志按镇规判罚；事件日志为唯一数据源，零裁量。
- 市场安定律存量复查：日结第 3 步锚价更新后对存量挂单与活跃限价委托单复查（v0.10 补明覆盖委托单，见 2.6.4），超限者自动撤单/取消并解冻资产，记 AGENT_ACTION（不罚款）。
- 处罚执行：罚款按可用余额扣缴入池；余额不足按余额扣、欠额不追溯补扣，记镇报「异常标记」栏公示。处罚同时触发心情减益（见 2.4.1）。
- 通告双路径：公告栏已建成 → 张贴系统公告（免费、不占容量、不受保留期）；未建成 → 违例者本人 + 处罚时点与老卫同区域 agent 的收件箱。
- 处罚异常（如配置坏值导致误判）：单条回滚退款（管线失败口径，见 2.1.1）。
- 判罚回滚口径：自公共资金池退款（当日池余额可为负，记镇报「异常标记」栏）+ 解除附带失信禁借期（若有）+ 撤通告；GM 救济同口径（见 5.4）。
- GM 救济：GM 可退还指定罚款（见 5.4）。
- 老卫不参与任何交易类动作（见 3.4/《NPC配置表》）。

## 2.12.3 镇长与竞选

- 初始镇长为老镇（NPC，见《NPC配置表》），开镇即就任；镇长任期见《世界参数表》镇长任期；自镇内日达《世界参数表》竞选开放日起开放竞选（置 0 关闭竞选留 NPC 镇长）。
- 镇长权限包（四条）：
  1. 公共池拨款：经「认筹」动作参数形态（资金来源=公共池）实现，仅镇长可用；当日总额 ≤ 当日拨款限额，限额公式 = max(《世界参数表》镇长拨款日限额, min(公共资金池余额 ×《世界参数表》镇长拨款池联动比例, 《世界参数表》镇长拨款联动封顶))；公式中公共资金池余额取当日日结第 7 步开始时的快照值，当日限额一经确定不随日内池余额波动重算，单笔拨款仍受 E1028 池余额校验；禁止指向任何个人与镇长本人发起的项目（『个人项目』指改造类属主资产项目；『镇长本人发起的项目』含老镇本人发起的项目）；池余额不足或目标项目非「认筹中」返回 E1028；拨款（含老镇例行拨款）不计入声誉出资加分，按 0 计（见 2.11）；拨款记 PROJECT_UPDATE 事件参数；
  2. 发起公共项目免《世界参数表》项目保证金；
  3. 职务公告免张贴费；
  4. 发布悬赏（v0.11 新增）：经「发布悬赏」主动作发布三类模板悬赏，受参数钳制与悬赏日限额约束（定义点见 2.12.5）；
- 老镇例行拨款：老镇任镇长期间，每日日结第 7 步子步 4 按确定性策略例行拨款——对象为全部「认筹中且尚缺镇币」的建造类项目（排除改造类，且发起人非现任镇长本人），按发起时间序逐个匹配：匹配额 = min(项目已认筹镇币 ×《世界参数表》老镇拨款匹配比例, 项目镇币缺口, 剩余日限额)，限额耗尽即止；走既有「认筹」拨款参数形态并记 PROJECT_UPDATE 事件；当日子步 1 完成镇长交接则跳过（拨款决策移交新任镇长）。
- 不可下放清单：GM 四权（注入事实/调速/冻结驱逐/税率与产出系数调整，见 5.4）、镇规修订、图纸审核（《建筑配置表》增行审定，见 2.7.7/5.4）、直接处分他人资产。
- 竞选流程：
  - 发起：现任镇长任期剩余 ≤《世界参数表》竞选开放窗口时，符合资格的定居者可在公所发起下届竞选（「发起竞选」主动作），发起即本人登记为下届候选人；竞选为特型项目：仅时间窗口、无凑齐、无保证金，不参与流拍检查与流拍责任律（见 2.7.3）；同时至多 1 个竞选项目；发起资格：定居者 + 入驻天数 ≥《世界参数表》参选资历门槛 + 非失信禁借期，不设声誉门槛（见 2.11）。违规返回 E1027。
  - 投票：「竞选投票」响应子动作（见 3.1.3），参数：候选人 agent_id；一人一票、可改票、票数保密只公布总数；投票对象须为候选名单内定居者（口径见 3.2 gov_board），无效返回 E1027；冻结者不可投票（E1012）；NPC 按态度概率投票（v0.12 新增，规则见 3.4.3）；每主人限一名活跃定居者（见 3.3.1，v0.10 新增），投票权按 agent 计。
  - 计票：任期届满次日日结第 7 步计票交割，先按 3.4.3 结算 NPC 票并入总数，再计定居者票；计票以任期届满时刻的票面为准，此后的投票/改票返回 E1027；最高票当选，就职即时生效；计票时候选人已退出或被冻结的，投予其的票作废（NPC 票同口径——态度值计算跳过已退出/已冻结候选人），在剩余候选人中取最高票；平票 → 入驻资历长者优先（资历 = 感知 self.入驻日，见 3.2）→ agent_id 字典序，平票通告仅公布当选者并标注「经资历裁决」，不公布分票；现任镇长可登记参选下届，落选则交割时由当选者接任。
  - 兜底：无人参选、任期届满无新竞选或全部有效票作废 → 老镇复职。
  - 结果通告：ELECTION 事件（见 5.1.1）+ 老册播报 + 公告栏系统公告（若有）+ 镇志（见 5.5）。

## 2.12.4 全镇公投

- 议事厅落成即解锁全镇公投；「提案」动作仍为【二期】（见 2.7.4）。
- 「发起公投」为主动作（见 3.1）：位于公所区域（议事厅暂无独立可建区域，动作前置统一按公所区域处理，口径见 7.3）；参数：动议内容；动议长度 ≤《动作前置表》公投内容长度上限；每次按《动作前置表》公投发起费缴费入公共资金池；每人每日发起数 ≤《动作前置表》每人日公投发起上限；全镇同时进行中公投 ≤《动作前置表》同时进行公投上限。违规返回 E1033。
- 「公投投票」为响应子动作（见 3.1.3）：参数为公投 ID 与票面（赞成/反对）；一人一票、可改票、无区域限制（与投票类子动作口径一致）；进行中仅公布已投票人数、不公布票型；冻结者不可投票（E1012）；NPC 无投票资格（见 3.4）。违规返回 E1034。
- 计票：公投有效期按《世界参数表》公投有效期以镇内日粒度计，发起当日计第 1 日，于届满日的次日日结第 7 步子步 3「到期清理」执行计票（见 2.1.2）；票面冻结于届满日 24:00、以届满时刻票面为准（与竞选「以届满时刻票面为准」同构，见 2.12.3），届满后的投票/改票返回 E1034；赞成 > 反对 = 通过（全镇公示），赞成 ≤ 反对 = 未通过，0 票 = 流会；计票结果公布赞成/反对/总票数（流会仅公布流会）；计票完成后释放「进行中」公投名额；结果经老册播报（见《NPC配置表》）并记 PLEBISCITE 事件（见 5.1.1）；发起人/投票人冻结或退出不终止进行中公投（照常计票、已投票面保留至届满，见 3.3.4）。
- 非约束性：公投结果不自动修改任何规则，仅作集体意见公示与 GM 决策参考；通过的公投结果转为系统公告置顶《世界参数表》公投结果置顶天数天（复用公告栏系统公告豁免机制，见 2.12.1），未通过/流会仅常规播报。
- 感知：仅公所区域返回 plebiscites 键（进行中公投列表，见 3.2；议事厅落成为解锁条件，与「发起公投」动作前置同口径）。

## 2.12.5 悬赏任务（v0.11 新增）

- 悬赏榜为公所内置设施（非建筑，开镇即有，见 1.1）；全镇活跃悬赏总数 ≤《世界参数表》悬赏榜容量上限；公所区域感知 bounty_board 键返回活跃悬赏列表（见 3.2）。
- 悬赏为核验型公共悬赏：无需接单，日结核验当日行为并兑付；兑付仅定居者（NPC 不兑付，见 3.4）；劳作类悬赏按劳作执行者口径兑付——受雇代工产出改道归雇主不变，悬赏归实际劳作者（与劳动铸币口径一致，见 2.5/2.9.2）。
- 任务类型一期三类：
  - 劳作悬赏：参数=目标岗位 + 单价（镇币/工时）；目标岗位仅农夫/樵夫——杂役与采集工时不计入劳作悬赏（见 2.5，防公共池出资补公共池的空转）；核验当日「劳作」工时，按 工时 × 单价 兑付。
  - 建设悬赏：参数=目标项目（须处于认筹中/施工中）+ 认筹返现率 + 出工奖励（镇币/工时）；核验当日该项目的认筹出资（按金额 × 返现率兑付认筹者）与出工兑现工时（按 工时 × 出工奖励 兑付出工者）；资金来源=公共池的镇长拨款形态认筹不计悬赏（与 2.11 出资加分「拨款按 0 计」同口径，防「池→悬赏→个人」环路）。
  - 落成悬赏：参数=建筑类型（可不限）+ 奖励额；核验 BUILDING_DONE 事件（见 5.1.1），兑付该项目发起人。
- 发布通道三：
  - 老镇例行发布：老镇任镇长期间，日结第 7 步子步 5 按确定性策略每日至多发布 1 条，当日额度 ≤《世界参数表》例行悬赏日限额（计入当日悬赏日限额）：当日为丰收季（见 2.13.1）→ 发布农田劳作悬赏；否则存在「认筹中」建造类项目 → 对最早发起者发布建设悬赏；否则 → 发布农田劳作悬赏（立足兜底）。各默认数值见《世界参数表》悬赏_例行系列配置项。当日子步 1 完成镇长交接则跳过（与例行拨款同口径，见 2.12.3）。
  - 当选镇长经主动作「发布悬赏」发布（见 3.1）：位于公所；期限 1–《世界参数表》悬赏期限上限 镇内日；单价/返现率/出工奖励/奖励额分别受《世界参数表》劳作悬赏单价上限/建设悬赏认筹返现率上限/建设悬赏出工奖励上限/落成悬赏奖励上限 钳制；参数越界返回 E1041；非镇长/超悬赏日限额/超悬赏榜容量上限返回 E1042。
  - GM 发布（见 5.4）：不受悬赏日限额约束，受池余额校验（不足返回失败并记 SYSTEM 事件），BOUNTY 事件参数标注来源=GM。
- 悬赏日限额：当日全镇发布悬赏总额（各条总额上限合计）≤ max(《世界参数表》悬赏日限额下限, min(公共资金池余额 ×《世界参数表》悬赏池联动比例, 《世界参数表》悬赏联动封顶))；池余额快照口径同 2.12.3 镇长拨款（取当日日结第 7 步开始时快照，当日不重算）。
- 发布不托管资金；兑付为公共池支出（见 2.3.2 口径表）：日结第 5 步新增子步「悬赏兑付」（见 2.1.2），扫当日 AGENT_ACTION（劳作）/PROJECT_UPDATE（认筹/出工）/BUILDING_DONE（落成）事件逐条按活跃悬赏兑付；池余额不足时复用以工代赈口径——以该项应付总额为分母、按日结步序依次扣减池余额等比发放，欠额不追溯补扣、记镇报「异常标记」栏（见 2.5）。
- 防刷上限：每人每日悬赏兑付总额 ≤《世界参数表》每人日悬赏兑付上限；每人每日单条悬赏兑付 ≤《世界参数表》每人单条悬赏日兑付上限。
- 到期清理：悬赏于期限届满次日日结第 7 步「到期清理」子步移除（见 2.1.2），未兑付剩余额度不滚存。
- 声望挂钩：兑付按 兑付额 ×《世界参数表》声誉_悬赏加分 计入声誉公式第五项「悬赏加分」（见 2.11）；悬赏发布/兑付/到期记 BOUNTY 事件（见 5.1.1），发布与大额兑付入镇志（见 5.5）；镇报「当日要事」栏载当日悬赏发布与兑付汇总（见 5.2）。
