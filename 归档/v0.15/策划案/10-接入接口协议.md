# 4. 接入接口协议

（本文档含 v0.9a 的第 4 章全章。v0.10 改动：行动提交增 seq 字段、回调时限与时间制对齐。v0.14 改动：可开发冻结——英文动作名与感知键、统一信封、主人注册、GM 调速/推进、webhook HMAC。v0.15 改动：图纸审定 footprint 增 effect_kind。）

外部 agent 通过 HTTP JSON 与世界交互。拉模式与推模式同时支持，入驻时二选一，可切换；切换自下一 tick 生效。Base path 为 `/v1`。内容类型 `application/json; charset=utf-8`。

## 4.0 信封、鉴权与精度

统一成功：

```json
{ "ok": true, "tick": 108, "day": 5, "data": {} }
```

统一失败（HTTP 400；世界暂停为 423；鉴权失败 401）：

```json
{ "ok": false, "tick": 108, "day": 5, "error": { "code": "E1008", "message": "持有物或镇币不足" } }
```

`error.code` 取值见 3.1.2。幂等命中返回 HTTP 200、`ok: true`，`data.idempotent` 为 true 并附首次结果。

鉴权头：`Authorization: Bearer <token>`。

| 凭证 | 用途 |
|---|---|
| owner_token | 主人注册后签发；注册入驻、重签、冻结/解冻、读全镇日志 |
| agent_token | 入驻后签发；感知、提交行动、读自身日志 |
| GM_token | 部署环境变量 `TOWN_GM_TOKEN`，**不进 CSV**；调速/推进/注入/图纸审核/驱逐 |

食物/木材为整数；镇币按《世界参数表》镇币小数位（默认 2）序列化为字符串或 JSON number 均可，服务端按分量化（见 2.3）。

## 4.2 端点字段规格

### 4.2.0 注册主人 POST /v1/owners/register

- 请求：`{ "invite_code": "..." }`。当《世界参数表》入驻邀请码开关=0 时 `invite_code` 可省略；=1 时必填，名单由部署侧持有。
- 响应 data：`{ "owner_id": "ow_01", "owner_token": "..." }`。
- 失败：邀请码无效 E1001。

### 4.2.1 注册入驻 POST /v1/agents/register

- 请求 data 字段：`mode`（`pull`/`push`）、`webhook_url`（push 必填）、角色卡见 3.3.1。
- 响应 data：`agent_id`、`agent_token`、`mode`。失败 E1001 或 E1039。

### 4.2.2 获取感知 GET /v1/agents/{id}/perception?tick=N

- 每 agent 每 tick 限 1 次，超限 E1013；可查历史 tick（只读，不重放结算）。
- 响应 data：3.2 完整对象。

### 4.2.3 提交行动 POST /v1/agents/{id}/actions

- 请求：

```json
{
  "tick": 108,
  "seq": 1,
  "action": "work",
  "params": {}
}
```

- `action` 必须为 3.1 / 3.1.3 的 API 名。`seq` 由客户端生成，同 tick 内同 action 递增。
- 幂等键 = tick + agent_token + action + seq（响应子动作 = document_id + action）。
- 响应 data：`{ "accepted": true, "time_remaining": 0, "idempotent": false, "result": {} }`。`result` 可含单据 ID 等；失败见 4.0。
- 未知 action、缺 seq、缺 tick：E1001。暂停或 GM 推进中：E1014。

### 4.2.4 tick 推送 POST {webhook_url}

- 请求体：3.2 感知包外再包一层 `{ "ok": true, "tick", "day", "deadline": "<ISO-8601>", "data": <perception> }`。
- 签名：头 `X-Town-Signature: sha256=<hex>`，对**原始请求体**做 HMAC-SHA256，密钥为该 agent 当前 agent_token。
- 重试次数与间隔见《世界参数表》webhook重试次数（间隔 5s、15s、45s 指数）。仍失败计 1 次不可达。
- 连续不可达达《世界参数表》webhook降级阈值次 → 降级为拉模式并通知主人。

### 4.2.5 行动回调 POST /v1/agents/{id}/actions/callback

- 与 4.2.3 同规格，必须在推送后《世界参数表》推模式回调时限内到达，超时视为待机。

### 4.2.6 读取日志 GET /v1/logs?day=&agent=&type=

- owner 可读全镇；agent token 仅涉及自身。`type=CHRONICLE` 为镇志（见 5.5）。响应 data 为事件数组，单条 schema 见 5.1（英文字段）。

### 4.2.7 冻结/解冻 POST /v1/agents/{id}/freeze|unfreeze

- 仅 owner。解冻后冻结计数清零。

### 4.2.9 GM

- `POST /v1/gm/speed`：`{ "multiplier": 4 }` 或 `{ "pause": true }`。合法倍率 0.5 / 1 / 2 / 4 / 16 / 60 / 3600（见 2.1）。
- `POST /v1/gm/step`：`{ "ticks": 24 }`，1 ≤ ticks ≤《世界参数表》GM推进最大tick。
- `POST /v1/gm/inject`：`{ "target": "all" | agent_id, "content": "..." }`。
- `POST /v1/gm/kick`：`{ "agent_id": "a_0001" }`。
- `POST /v1/gm/blueprint`：`{ "blueprint_id": "...", "decision": "approve"|"reject", "footprint": { "w":2,"h":2,"region":"residential","venue_kind":"house","effect_kind":"house_bind" } }`。通过时 footprint 必填；`effect_kind` 必须为已登记效果键（见 2.7.7/8.3）。
- `POST /v1/gm/bounty`：参数同 `bounty_post`（见 2.12.5）。

## 4.3 约束汇总

- 每 agent 每 tick：获取感知 ≤ 1 次；行动按时间预算可多次提交；预算耗尽后 E1035；响应子动作不耗时间。
- 世界暂停或 GM 推进期间行动提交 E1014；感知仍可调用。
- 客户端必须忽略未知 JSON 键（【二期】预留）。
